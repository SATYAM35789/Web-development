Advanced useState(318) :-
- hamane apne folder mai bahut sari useState ki help se, stateVariable banayi hai, which is not good practice. There is a 
  way to handle many stateVariable :-
  - Maintain a object , and us object mai sari stateVariable rakh de in key:value pair, and object state ki tarah treat karle. 
    ex.
      Different stateVariable: 
        -const [pokemonList, setPokemonList] = useState([])
        -const [isLoading, setIsLoading] = useState(true)  
        -const [pokedexUrl , setPokedexUrl] = useState('https://pokeapi.co/api/v2/pokemon')
        -const [nextUrl, setNextUrl] = useState('')
        -const [prevUrl , setPrevUrl] = useState('') 

        Converted for, as object :-
          - const[pokemonListState, setPokemonListState ] = useState({}) : here useState take an variable.
          - implemented form :-
              const[pokemonListState, setPokemonListState ] = useState({
                pokemonList : [],
                isLoading : true,
                pokedexUrl : 'https://pokeapi.co/api/v2/pokemon',
                nextUrl : '',
                prevUrl : ''
              })

          - How to implement this way or method:-
            - Agar is stateVariable as Function use karna hai toh function variable call karenge:
              setPokemonListState():-
               -is parenthesis ke ander, pahle is object jo bhi hai usko unpacked karenge, with this=> ({...pokemonListState})
               - jo bhi object or functionality humko chahiye usko override kar denge parenthesis ke ander, override means jo object
                 hamne define kiya hai waise he. {isLoading:true}
                 overall aisa dikhega : setPokemonListState({...pokemonListState, isLoading:true})
               - In statevariable :har jagah unpacked karne ki zarurat nahi hai ab, ab iska stateVariable.functionality ad kar sakte hai 
                 jaise : pokemonListState.pokedexUrl
               - functionality ke liye uppar wala method.

            - occured problem:- so yaha do pokemon ki state set ho rhai, means jab hum do setPokemonListState ko call kar rahe hai
              toh do baar value set ho ja rahi hai, isme aisa nahi hota ki pahle ek baar value set ho jaye, uske baad update ho jaye. 
              uske uppar, setfunction call karte hai kisi bhi stateVariable par, ustime agar hamne 5 baar call kara toh pahle pahle wali 
              state lag jayegi, phir uske uppar duri wali lagegi an so on. Jo final setfunction update hota hai wahi mana jata hai. 
               -how to avoid this : 
            
            -Queueing a series of state Updates :- 
              - maan lo ek number hai kisko hum set kar rahe hai, usko lagatar tin baar kar diye, ham lagege ki tin bar change hogi,
               but value change hogi according to last set.  beccaue React wait until all code in the event handles has run before
               processing your state update. means pahle toh react wait karta hai do re-render ke bich mai , jo rerenders hai wo execute 
               ho jaye, uske baad wo sari ki sari event ko render karta hai. 
               - Updating the same state multiple times before the next render then, you have to send a updaterFunction. 
                 -means agar hum ek call function pass kardo jo , sari ki sari fun ko queue kar deta hai. render hone se pahle callback function
                  queue pahle excute hoga uske baad render hoga. 

              - Agar do rerenders ho rahe hai, agar hum directly value ko update karte hai, like state variable pokemonListState ko , jaha jaha 
               state variable call hoga,  us time ki actuall value pick ki gayi hai, aur phir un tino ko process karte hai lakin
               callback fun pass karne ke baad, iska jo bhi output future mai aa sakta hai, wo value set hogi. toh isiliye sari callback
               fun queue ho jati hai.
